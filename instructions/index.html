Здесь всё, что нужно сделать руками после того, как сайт уже собран. Идите сверху вниз. Каждый шаг заканчивается понятным результатом: что вы должны увидеть, прежде чем переходить дальше.

  • GitHub. Место, где лежит копия кода: github.com/lecmedea/catalog-max. Страницы для посетителей собираются из этого кода и публикуются на адрес выше.
  • Supabase. Сервис в интернете. В нём живут каналы, категории, пользователи и письма «подтвердите почту». Регистрация бесплатная для старта.
  • Проект Supabase. Одна отдельная база. Для этого каталога нужен один проект.

  • Secret key. Ключ, который начинается с sb_secret_, или длинный ключ service_role. В этот сайт его вставлять не нужно. Если такой ключ попадёт в файл или в чат, человек с ним сможет читать и менять всю базу.
  • .env.local. Текстовый файл в папке сайта. В нём три строки: адрес базы, ключ и адрес сайта. Точка в начале имени делает файл скрытым в Finder. На GitHub этот файл не попадает.
  • Миграция. Готовый текст, который один раз создаёт все таблицы. Он уже лежит в проекте. Его копируют в SQL Editor и нажимают Run.
  • Терминал. Программа на Маке: Finder → Программы → Утилиты → Терминал. В неё вставляют команды. Одна команда — одна строка, затем клавиша Return.

1. Зарегистрироваться в Supabase и создать проект

  1. Откройте в браузере https://supabase.com.
  2. Нажмите Start your project или Sign in. Удобно войти через GitHub тем же аккаунтом lecmedea. Можно зарегистрироваться и по электронной почте.
  3. Если Supabase прислал письмо, откройте его и подтвердите адрес. Без этого проект может не создаться.
  4. На главной панели нажмите New project.
  5. Если спросят организацию, оставьте ту, которую Supabase создал вместе с аккаунтом, или назовите её своим именем.
  6. В поле имени проекта напишите catalog-max.
  7. В поле пароля базы придумайте длинный пароль и запишите его в заметки на телефоне или в менеджер паролей. Это пароль от самой базы, не от входа в каталог. Каталог попросит у вас другой пароль, на шаге 8.
  8. Регион выберите европейский, ближе к вам. Подойдёт Frankfurt. Регион потом не меняется.
  9. Нажмите Create new project и подождите одну-две минуты. Пока проект готовится, кнопки базы серые. Дальше идите, когда открылась страница проекта и слева появилось меню.

Результат шага: вы внутри одного проекта Supabase, сверху видно его имя.

2. Скопировать адрес проекта и ключ

  1. На странице проекта нажмите кнопку Connect. Она обычно сверху.
  2. Если спросят каркас, выберите Next.js.
  3. Найдите строку адреса. Она выглядит так: https://abcdefgh.supabase.co. Скопируйте её целиком, вместе с https://, без пробела в конце.
  4. Найдите ключ, который начинается с sb_publishable_. Скопируйте его целиком.
  5. Если в окне Connect ключа нет, откройте слева внизу шестерёнку Project Settings, затем раздел API Keys. Адрес проекта лежит там же. Отдельной страницы Settings → API в новом кабинете Supabase нет.
  6. Ключ sb_secret_... и длинный ключ, который начинается с eyJ, не копируйте.

Держите адрес и publishable key в черновике заметки, пока не вставите их в файл на следующем шаге. После этого черновик можно стереть.

3. Положить ключи в файл .env.local

Файл-образец уже лежит в папке сайта и называется .env.example. Рабочий файл называется .env.local. Его создают копией образца и заполняют своими значениями.

  1. Откройте Терминал: Finder → Программы → Утилиты → Терминал.
  2. Вставьте первую команду и нажмите Return. Она просто открывает папку сайта:
cd "/Users/sergejbezaev/Documents/ChatGPT/catalog-max"
  1. Вставьте вторую команду и нажмите Return. Она делает рабочую копию образца. Если файл уже был, команда спросит подтверждение словом overwrite. Напишите y и нажмите Return только если в старом файле ещё нет ваших ключей.
cp -i .env.example .env.local
  1. Вставьте третью команду. Откроется TextEdit с тремя строками:
open -e .env.local

В файле будет примерно это:

NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
NEXT_PUBLIC_SITE_URL=http://localhost:3000
  1. Если TextEdit показывает меню Формат, выберите Сделать простым текстом. Файл должен остаться обычным текстом, без жирного шрифта и без расширения .rtf.
  2. В первой строке замените https://your-project.supabase.co на адрес из шага 2. Имя слева, NEXT_PUBLIC_SUPABASE_URL, не трогайте. Пробела до и после знака = быть не должно.
  3. Во второй строке замените sb_publishable_... на свой publishable key. Кавычки вокруг ключа не ставьте.
  4. Третью строку оставьте как есть: http://localhost:3000. Её меняют только на шаге 15, когда появится адрес в интернете.
  5. Сохраните файл: клавиши Command и S. Закройте TextEdit.

Проверка. Снова вставьте в Терминал:

grep -c NEXT_PUBLIC .env.local

Должно напечататься число 3. Это значит, что в файле три нужные строки. Сами ключи на экран эта команда не выводит.

В Finder этот файл скрыт, потому что имя начинается с точки. Чтобы увидеть скрытые файлы, откройте папку сайта и нажмите вместе Command, Shift и точку. Повторное нажатие снова их прячет.

4. Создать таблицы через SQL Editor

Это и есть миграция. Текст уже написан. Его нужно выполнить в базе один раз. Отдельную программу Supabase на Мак ставить не нужно.

  1. В Терминале, всё в той же папке, вставьте команду. Откроется длинный текстовый файл:
open -e "/Users/sergejbezaev/Documents/ChatGPT/catalog-max/supabase/migrations/20261115094405_catalog_schema.sql"
  1. В TextEdit нажмите Command и A, затем Command и C. Выделится и скопируется весь текст, от первой строки до последней.
  2. Вернитесь в браузер, в свой проект Supabase.
  3. Слева нажмите SQL Editor.
  4. Нажмите New query, если открыт старый пустой лист. Большое поле должно быть пустым.
  5. Нажмите в это поле и вставьте текст: Command и V.
  6. Нажмите зелёную кнопку Run. На клавиатуре то же самое делают Control и Enter.
  7. Подождите. Внизу должно появиться Success. Фраза No rows returned тоже нормальна: команда создаёт таблицы, а не показывает список каналов.
  8. Слева откройте Table Editor. В списке должны быть таблицы profiles, categories, channels, channel_stats, platforms, favorites и channel_verifications.
  9. Откройте таблицу categories. Там уже семь строк: Нейросети, Боты, Новости, Обучение, Творчество, Бизнес, Инструменты. Каналов и инструментов там ещё нет. Их добавляют позже, с сайта.

Второй раз этот текст запускать не нужно. Если Run пишет, что объект already exists, таблицы уже созданы. Оставьте их как есть.

Команда supabase db push делает то же самое, но через отдельную программу на компьютере. Для этой инструкции она не нужна: SQL Editor уже выполнил работу.

5. Разрешить адреса входа

Когда человек регистрируется или просит новый пароль, Supabase отправляет письмо со ссылкой. Ссылка имеет право вернуть человека только на адрес из белого списка. Иначе письмо откроется, а сайт покажет ошибку входа.

Сейчас сайт живёт по адресу http://localhost:3000. Именно его и вносят в список.

  1. В левом меню Supabase откройте Authentication.
  2. Откройте страницу URL Configuration.
  3. В поле Site URL напишите ровно это, без слэша в конце:
http://localhost:3000
  1. Ниже блок Redirect URLs. Нажмите Add URL и вставьте первую строку:
http://localhost:3000/auth/callback
  1. Нажмите Add URL ещё раз и вставьте вторую строку:
http://localhost:3000/auth/confirm
  1. Нажмите Save.

Проверьте четыре вещи: в начале стоит http, не https; порт именно 3000; после адреса нет пробела; в списке есть и /auth/callback, и /auth/confirm.

Первый адрес принимает ссылку из письма, когда Supabase возвращает код входа. Второй нужен, если шаблон письма передаёт token_hash. Оба уже умеет сам сайт.

6. Пароль, письма и своя почта

  1. В том же разделе Authentication откройте Providers, или Sign In / Providers, если меню называется так.
  2. Откройте Email. Переключатель должен быть включён.
  3. Пункт подтверждения почты, Confirm email, оставьте включённым. Тогда человек попадает в кабинет после письма, а не сразу.
  4. Найдите поле минимальной длины пароля, Minimum password length, и поставьте 8. На сайте пароль тоже от 8 до 72 символов. Если в Supabase стоит больше, сайт пароль примет, а Supabase его отвергнет.
  5. Сохраните изменения на этой странице, если есть кнопка Save.

Встроенная почта Supabase для нового проекта отправляет примерно два письма в час. Для первой регистрации и одного сброса пароля этого хватает. Письмо ищите во входящих и в папке «Спам». Если за час вы запросили письмо третий раз, следующее придёт после паузы.

Когда каталогом начнут пользоваться другие люди, подключите свою почту. В Supabase это страница Authentication → Emails → SMTP Settings. Туда вписывают адрес сервера, порт, логин и пароль приложения. У Яндекса и Gmail это отдельный пароль приложения, его создают в настройках почты, а не вводят обычный пароль от ящика. После смены SMTP запросите письмо заново: старые ссылки остаются со старым отправителем.

Никнейм на сайте: от 3 до 24 знаков, только латинские буквы, цифры и подчёркивание. Пример: max_catalog. Имя кириллицей в никнейм не ставится. Имя для людей живёт в отдельном поле анкеты.

7. Запустить сайт на этом компьютере

  1. Откройте Терминал. Если он уже открыт с прошлого шага, новое окно не нужно.
  2. Вставьте две команды по очереди. После каждой нажмите Return.
cd "/Users/sergejbezaev/Documents/ChatGPT/catalog-max"
npm run dev
  1. Подождите, пока в тексте появится строка Local: http://localhost:3000.
  2. Откройте в браузере http://localhost:3000.
  3. На главной должны быть жёлтый фон, опал, поиск и категории. Надписи «База ещё не подключена» быть не должно. Если она осталась, остановите сайт и запустите снова: файл с ключами читается в момент запуска.

Окно Терминала не закрывайте, пока смотрите сайт. Закрытие окна останавливает сайт.

Остановить сайт вручную: щёлкните в окно Терминала и нажмите Control и C. Запустить снова — те же две команды.

Если Терминал пишет command not found: npm, закройте Терминал полностью и откройте его заново. Node на этом Маке подключается при открытии окна.

Если Терминал пишет, что порт 3000 занят, сайт уже запущен в другом окне. Найдите то окно или откройте http://localhost:3000.

8. Зарегистрировать свой аккаунт

  1. На сайте нажмите Войти, затем ссылку на регистрацию.
  2. Введите почту, которую реально открываете, пароль от 8 символов и никнейм латиницей.
  3. Отправьте форму. Сайт попросит открыть письмо.
  4. Откройте письмо от Supabase и нажмите ссылку. Браузер должен вернуться в кабинет.
  5. Если письма нет, проверьте «Спам» и лимит из шага 6. Если ссылка открывает страницу ошибки кода, вернитесь к шагу 5 и сверьте оба адреса, /auth/callback и /auth/confirm, затем запросите письмо ещё раз.

Забыли пароль: на странице входа есть ссылка восстановления. Новое письмо ведёт на страницу смены пароля. Старый пароль после этого не подходит.

9. Назначить себя администратором

Регистрация создаёт обычного пользователя. Кнопки «Админка» у него нет. Первого администратора назначают одной командой в SQL Editor. Так устроено специально: форма регистрации роль администратора не выдаёт.

  1. В Supabase откройте SQL Editor → New query.
  2. Вставьте текст ниже. В кавычках замените почту на ту, которой только что зарегистрировались. Буквы должны совпасть полностью.
update public.profiles set role = 'admin' where email = 'you@example.com';
  1. Нажмите Run. Внизу будет Success. Если написано, что обновлено 0 строк, почта не совпала. Откройте Table Editor → profiles и скопируйте email оттуда в команду.
  2. Вернитесь на сайт, обновите страницу. В шапке появится ссылка Админка.

Снять с себя админку через ту же форму нельзя: защита не даёт администратору запретить вход самому себе.

10. Заполнить анкету

  1. Откройте Кабинет → Анкета.
  2. Имя или псевдоним можно написать по-русски. Это имя видят люди.
  3. Никнейм уникальный. Если он занят, форма об этом скажет.
  4. Фото — файл JPEG, PNG или WEBP, до 2 МБ.
  5. Контакт в MAX — ник или ссылка, по которой с вами говорят о рекламе.
  6. Агентство можно оставить пустым.
  7. О себе — до 300 символов.
  8. Тип аккаунта: «Владелец каналов» или «Рекламодатель / Агентство».
  9. Галочка «показывать контакт» включает контакт на карточках ваших одобренных каналов. Без галочки на карточке будет написано, что владелец скрыл контакт.
  10. Сохраните анкету. Смену пароля делайте в нижнем блоке той же страницы. Нужны текущий пароль и новый.

11. Добавить канал и код проверки

  1. Откройте Кабинет → Каналы и создайте канал.
  2. Название — как канал называется в MAX.
  3. Ссылка обязана начинаться с https://max.ru/ или с поддомена max.ru. Ссылку из другого мессенджера форма не примет.
  4. Выберите категорию, напишите описание, при желании укажите цену рекламы в рублях и контакт менеджера.
  5. Аватар и галерея: до шести картинок, каждая до 2 МБ, форматы JPEG, PNG или WEBP.
  6. Сохраните. Канал получает статус «на модерации». В общем каталоге его ещё не видно.
  7. На странице этого канала в кабинете появится код вида maxstat-verify-8492. Цифры у каждого канала свои.
  8. Откройте свой канал в мессенджере MAX и временно вставьте этот код в описание канала. Так при проверке видно, что канал ваш.
  9. После одобрения код из описания MAX можно убрать.

Свой канал можно править: описание, категорию, цену, контакты, картинки. Статус, галочку и цифры подписчиков меняет только администратор. Если заявку отклонили, причина написана на карточке в кабинете. Канал можно удалить. Число своих каналов не ограничено.

Чужой одобренный канал сохраняют в Избранное кнопкой на его странице. Список лежит в кабинете.

12. Одобрить канал в админке

  1. Откройте Админку. Там список заявок, в том числе код проверки.
  2. Сверьте код с описанием канала в MAX, если владелец его поставил.
  3. Впишите подписчиков, средний охват и ERR, если цифры уже известны. Пустые нули тоже можно оставить и дописать позже.
  4. Чтобы канал появился в каталоге, выберите статус «одобрен» и сохраните.
  5. Синяя галочка «проверен» ставится отдельно. Она значит, что канал проверен, а не просто допущен в список.
  6. Если заявку нужно вернуть, выберите «отклонён» и обязательно напишите причину. Без причины форма не сохранится. Владелец увидит этот текст у себя в кабинете.
  7. Точка на графике: дата, число подписчиков и охват за этот день. Две и больше точек рисуют график на карточке канала.

Обычный пользователь страницу админки не откроет: его возвращает в кабинет. Гостя, который не вошёл, со страниц кабинета и админки возвращает на вход.

13. Наполнить раздел инструментов

Страница Инструменты — витрина ботов, аналитики, автопостинга и рекламных сервисов для MAX. Её видят все. Кнопки «добавить» на самой витрине нет.

  1. Войдите администратором.
  2. Откройте Админка → Инструменты.
  3. Заполните название, короткое описание, адрес сайта https://..., тип и модель оплаты: Бесплатно, Freemium или Платно.
  4. Логотип необязателен. Если добавляете, это JPEG, PNG или WEBP до 2 МБ.
  5. Сохраните. Карточка появится на витрине. Там же её можно изменить или удалить.

Категории каталога правятся в Админка → Категории. Семь стартовых уже созданы миграцией. Пользователей, роли и блокировку смотрят в Админка → Пользователи.

14. Если что-то не получилось

  • На главной написано «База ещё не подключена». В .env.local нет адреса или ключа, либо сайт запущен до сохранения файла. Остановите его клавишами Control и C и снова выполните npm run dev.
  • Категории пустые. Миграция из шага 4 ещё не выполнена или выполнена в другом проекте Supabase. Откройте Table Editor того проекта, чей адрес стоит в .env.local.
  • Регистрация пишет, что почта уже есть. Этот адрес уже создан. Войдите или восстановите пароль.
  • Пароль не принимается. На сайте нужно от 8 до 72 символов. В Supabase минимальная длина тоже должна быть 8. Очень длинный пароль из одних русских букв иногда не проходит: у Supabase есть ещё предел в 72 байта, а русская буква занимает больше одного байта. Для первого пароля возьмите смесь латинских букв и цифр длиннее 8 знаков.
  • Письмо не приходит. Папка «Спам», лимит около двух писем в час, затем своя SMTP-почта из шага 6.
  • Ссылка из письма открывает ошибку. В URL Configuration нет http://localhost:3000/auth/callback или сайт в момент переходa был выключен. Запустите npm run dev и запросите новое письмо.
  • Админки нет. Команда из шага 9 обновила 0 строк, почта не совпала, или страница не обновлена. Выйдите и войдите снова.
  • Свой канал не виден в каталоге. Он ждёт статуса «одобрен». До одобрения он виден только в кабинете владельца и в админке.
  • Ссылка на канал не сохраняется. Нужен адрес вида https://max.ru/имя.
  • Картинка не загружается. Нужен JPEG, PNG или WEBP не тяжелее 2 МБ. Миграция создаёт хранилища avatars, channel-media и platform-logos. Если таблиц нет, картинкам тоже некуда сохраниться: сначала шаг 4.

15. Открыть сайт не только на этом Маке

Адрес localhost существует только на вашем компьютере. Витрина для остальных уже опубликована: https://lecmedea.github.io/catalog-max/. На ней можно смотреть страницы и эту инструкцию. Регистрация, письма и кабинет на GitHub Pages не заработают: там нет сервера Next.js и нет базы.

Чтобы люди могли входить, добавлять каналы и проходить модерацию, тот же код с GitHub подключают к хостингу, который умеет Next.js. Прямой путь — Vercel.

  1. Откройте https://vercel.com и войдите через GitHub аккаунтом lecmedea.
  2. Нажмите Add New → Project и выберите репозиторий catalog-max.
  3. Прежде чем нажать Deploy, откройте настройки переменных окружения и добавьте те же три имени, что в .env.local: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY и NEXT_PUBLIC_SITE_URL.
  4. В NEXT_PUBLIC_SITE_URL пока можно поставить временную заглушку http://localhost:3000. После первого адреса Vercel её заменяют.
  5. Нажмите Deploy и дождитесь зелёного статуса. Vercel покажет адрес вида https://catalog-max-....vercel.app.
  6. Вернитесь в настройки проекта Vercel, в Environment Variables, и замените NEXT_PUBLIC_SITE_URL на этот адрес, без слэша в конце. Сохраните и нажмите Redeploy, чтобы сайт пересобрался с новым адресом.
  7. В Supabase, на странице Authentication → URL Configuration, поставьте Site URL равным адресу Vercel.
  8. В Redirect URLs добавьте две строки с этим адресом. Подставьте свой домен вместо примера:
https://catalog-max-....vercel.app/auth/callback
https://catalog-max-....vercel.app/auth/confirm
  1. Сохраните URL Configuration. Запросите новое письмо регистрации уже с живого адреса. Старые письма ведут на localhost и с другого компьютера не откроются.

Пока шаг с Vercel не сделан, витрина для посетителей — https://lecmedea.github.io/catalog-max/, а полная копия с входом — http://localhost:3000 при запущенном Терминале.

16. Чего лучше не делать

  • Не вставляйте secret key и service_role в .env.local, в GitHub и в переписку.
  • Не отправляйте файл .env.local. В репозиторий он и так не входит.
  • Не запускайте длинный SQL из шага 4 второй раз.
  • Не придумывайте каналы и цифры статистики ради наполнения. В каталог попадают заявки владельцев после проверки.
  • Пароль базы Supabase и пароль от каталога — разные. Оба храните у себя.

Дальше обычная работа идёт на самом сайте: анкета, каналы, избранное и, для администратора, модерация.
